# Automatic capture

Home → Take a Pothole Photo extracts GPS locally, asks for privacy and location review, uses one-time device GPS for live camera captures where appropriate and requires a pin when location is missing. Independent street lookup runs after pin selection and refreshes when the pin moves. Optional Google address previews are separate and transient.

On Cloud Run the upload must complete automatic face/plate redaction before storage or verification. A failure blocks upload. The photo check starts automatically after successful upload and stored account consent; the server permits live Gemini processing only when paid mode and the image AI switch are enabled. With auto acceptance off, positive observations require review. Negative, uncertain and unavailable results are distinct; manual review is available only when an eligible server-issued verification ID exists. With image AI or paid mode disabled the analysis endpoint returns HTTP 503 without an ID; new Capture submissions (including manual review) are blocked. Resolve or explicitly accept this limitation before opening the pilot. Accepted captures are submitted only with confirmed location and valid server decisions. Duplicate evidence is not another distinct pothole; pending contributions earn no credit.

See [photo redaction](PHOTO_REDACTION.md), [location provenance](LOCATION_PROVENANCE.md) and [benchmark](BENCHMARK.md). Verify device GPS denial, missing EXIF, pin correction, failed redaction, provider failure, duplicate evidence, retries and exactly-once credit on isolated staging. No live tests are asserted.
