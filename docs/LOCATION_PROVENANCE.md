# Location data boundary — PR #8

## Governing published terms (reviewed 2026-11-27)

- [Google Maps Platform Terms](https://cloud.google.com/maps-platform/terms), §3.2.2 (application terms, privacy, location consent), §3.2.3 (restrictions on export, caching and content creation).
- [Service Specific Terms](https://cloud.google.com/maps-platform/terms/maps-service-terms), §6.1–6.3 (Geocoding). The direct-user caching exception is logically isolated to one end user; it is not blanket permission for shared pothole datasets. PatchUp chooses **no durable Google response storage**, a stricter boundary.
- [Geocoding policy and attribution](https://developers.google.com/maps/documentation/geocoding/policies). Inspect the rendered Google Maps attribution before launch; do not display Google results with a non-Google map.
- [Census TIGER/Line source](https://www.census.gov/geographies/mapping-files/time-series/geo/tiger-line-file.html) and [technical documentation](https://www.census.gov/programs-surveys/geography/technical-documentation/complete-technical-documentation/tiger-geo-line.html). U.S. Census Bureau TIGER/Line data are public-domain federal data; retain the Bureau's citation and disclaimer when repackaging. The Census Bureau does not endorse PatchUp, and road geometries/names may be inaccurate or out of date. This patch does not assert the city's dataset license.

## Data flow and launch gates

1. Before extraction or location requests, the user opts into the capture location workflow. Account consent is versioned and includes the public terms. Google address preview has a separate optional revocable checkbox. A fresh pin triggers a debounced independent lookup and, if opted in and enabled, a separate Google request.
2. Google response is an authenticated `no-store` preview, not a source of permanent fields. It is kept in transient component state, never in `roadLookups`, payloads, candidates, exported rows or the canonical road proof. Google response coordinates/place IDs are not needed. Use original photo/device GPS or reporter-selected coordinates. Do not trace Google road geometry or copy Google address suggestions into an independent entry.
3. Trusted road proof: local Census TIGER/Line 2025 ROADS or explicitly reuse-approved City centerlines, with ambiguity rejection. Reporter-observed fallback requires an affirmative independent-source attestation. This is not cryptographic proof that a human did not copy text from another source. The backend rejects Google provenance and marks new records `locationPolicyVersion: independent-v1`. Streets without a match require manual independent correction; no invented full address or ownership. The Census ROADS file does not provide house-number ranges; Google approximate address is preview only, exported street labels plus original coordinates are independent.
4. Historical records remain unverified by default. Public community lists and candidate matching exclude unverified historical potholes; public projections also suppress unknown-origin street labels as defense in depth. Existing records are not deleted. Community report/corridor routes and generation remain paused unless `PATCHUP_LOCATION_HISTORY_AUDITED=true`. Do not set it solely because CI passes. New photo verification/capture and individual contribution statistics can continue; the backfill must be reviewed and executed after remediation.
5. Google Sheets requests must obtain a server-approved snapshot before creating a spreadsheet. Rows contain the independently sourced street, original coordinates, record ID and provenance, not formatted addresses, old corridor labels, personal usernames or Google data. The API rejects unknown/mixed source snapshots. The sheet is written with RAW values. Email drafts are similarly checked before creation. Google Sheets itself is not a Maps licensing exemption.

## Prepare independent street dataset (separate from merge)

Use official 2025 Georgia county `ROADS` ZIP files from the Census Bureau's [2025 ROADS directory](https://www2.census.gov/geo/tiger/TIGER2025/ROADS/). For an Atlanta-city pilot, start with Fulton (13121) and DeKalb (13089), and add counties for the actual supported geographic scope. This patch ships **no road dataset**. Verify the official source, actual county coverage, file hashes, legal notice, and benchmark representative roads/intersections before deploying. Use a dedicated Python virtual environment and install `pyshp` from its trusted package source. Run `python scripts/prepare-tiger-roads.py --output /your/path/tiger-roads.json /your/path/tl_2025_13121_roads.zip /your/path/tl_2025_13089_roads.zip` after downloading official files. The converter records input hashes and filters to the existing Atlanta bounding box. It does not download or commit data. Configure `PATCHUP_TIGER_ROADS_FILE` to the provisioned trusted read-only file. The Cloud Run container template does not include that file; provision it in a reviewed image or read-only volume. Ensure resource use and coverage are tested. City lookup additionally needs `PATCHUP_CITY_ROADS_REUSE_APPROVED=true` and documented reuse rights; leave off otherwise. Census road name is not jurisdiction proof.

## Historical audit and remediation (separate, intentionally non-destructive)

- Stop all older backend instances before activating the new policy; otherwise old code could still write Google data. Leave billing and feature flags unchanged during merge.
- Run `node --experimental-strip-types scripts/audit-location-history.ts --project patchup-fff96 --database '(default)' --read-only` only in an authenticated, approved administrative environment with ADC. The script reads collection metadata/content but prints counts only; reads may count against Firestore allowances. It does not prove compliance or inspect every nested collection. Do not run it during CI/merge.
- Review all legacy `potholes`, `submissions`, lookup/cache records, corridor memberships, supplements, report snapshots, activity/notification text, audit records, logs, backups and external sheets/agency reports. Find Google-derived and unknown-origin values. Use original independent coordinates to re-match where provenance can be demonstrated. Quarantine unresolved records; delete restricted cached Google content under an approved remediation procedure, including `roadLookups` and `geocodeCache`; expiration by itself is not deletion. Review privacy/deletion requirements and retained agency copies. Never mark unknown data independent just because a new label matches.
- Rebuild affected segments and snapshots from verified independent records without destroying confirmed agency reference/status history. Verify all members and exports, including previously generated ones. Record dataset version, source, hashes and decision log. Set `PATCHUP_LOCATION_HISTORY_AUDITED=true` only after this review is actually completed. This PR provides a fail-closed hold and audit aid, **not an automated destructive migration**.
- Review actual customer agreement, public contact details and legal disclosures; verify authorization and browser behavior in staging. Keep `PATCHUP_GOOGLE_GEOCODING_ENABLED` and `PATCHUP_GOOGLE_GEOCODING_PREVIEW_APPROVED` false until live preview use is authorized. The old storage approval flag is retired. No new billing, IAM, credential, deployment or database mutations occur in the merge.

## Tests to run before activation

Code review is not a binding legal opinion or inspection of actual historical production data.
